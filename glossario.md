# Glossário

| Termo | Significado |
|---|---|
| **Acoplamento** | Grau de dependência entre módulos. A meta é reduzi-lo sem eliminar as relações necessárias. |
| **Adaptador** | Componente que converte uma interface em outra esperada por seus clientes. |
| **Coesão** | Grau em que os elementos de um módulo colaboram para um único propósito. |
| **Code smell** | Sinal de que o desenho pode dificultar manutenção; não é, isoladamente, prova de defeito funcional. |
| **DIP** | Princípio da Inversão de Dependência: módulos dependem de abstrações, não de detalhes concretos. |
| **Interface estável** | Contrato exposto por um módulo que permite mudar detalhes internos sem afetar seus consumidores. |
| **Módulo** | Unidade relativamente independente, como classe, pacote, componente ou serviço. |
| **Ocultamento de informação** | Encapsular decisões de projeto que podem mudar e expor apenas o necessário. |
| **Refatoração** | Mudança na estrutura interna sem alteração do comportamento externo. |
| **SOLID** | Conjunto de cinco princípios de projeto: SRP, OCP, LSP, ISP e DIP. |
| **Strategy** | Padrão que permite substituir uma regra ou algoritmo por outra implementação com o mesmo contrato. |
| **Objeto de valor** | Objeto que agrupa dados relacionados e é tratado pelo valor que representa. |
